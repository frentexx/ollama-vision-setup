# RDQ 需求規格：Padlet 作業牆自動建立網頁

## 一句話任務
在批改電腦的審核頁服務裡加「建作業牆」頁與後台，美術老師不開 agent，填表就建好 Padlet 作業牆並能一鍵進批改。

## ✅ 已確認
- 使用者只有**美術老師 1～2 位**（Ⅲ）
- 作業牆一律建在教室版帳號 **pad02_98** 底下，用現有 `.env` 的 Padlet key（Ⅲ）
- 跑在**這台批改電腦**，走校內網址，與審核頁同一服務（Ⅲ）
- 後台管兩件事：**已建作業牆清單**（網址、QR、繳交人數、一鍵抓作業寫草稿→審核）與**作業牆範本＋rubric**（Ⅲ）
- 建牆只能用 Padlet AI Recipe；新牆預設關留言，API 不能改設定、不能事後加區段（Ⅰ）
- **一個區段＝一份作業**：老師建牆時設定區段數量（1～8）與名稱；學生在各區段各貼一篇，批改單位是「學生×區段」，評語留在該篇（修訂 1）
- 範例改為攝影課：① 微距攝影 ② 人物攝影 ③ 風景攝影；rubric 用共同檢查點＋各作業檢查點（修訂 1）
- 網頁要有簡單操作引導：建牆頁上方五步驟＋「使用說明」分頁（含 .toml 說明）（修訂 1）

## ❓ 假設（未確認，已採預設值，隨時可推翻）
- 登入沿用審核頁**同一組密碼**，不分老師帳號 → 預設採共用密碼
- 建牆表單欄位：**班級、作業牆名稱、範本（下拉）、區段數量與名稱、補充說明（選填）**；截止日只寫進說明，不做自動關閉
- 第一個範本是「**攝影課三份作業（微距／人物／風景）**」，預設評分規準 `範例-攝影三作業.toml`
- 範本也允許老師在補充說明裡自由描述（不強制只能用範本）
- 後台 rubric 管理 = 選擇／上傳／線上編輯 rubric 文字檔；「老師隨手文字→rubric」仍由 Claude 協助，本期不做網頁版
- 建牆紀錄存本機 **data/boards.json**（不進 git）；批改在背景執行並顯示進度
- 老師若要在 Padlet 上手動改設定，需登入 pad02_98 或由你手動加他為管理員

## ➕ 已採納（象限Ⅳ）
- 建牆後自動讀回驗證欄位是否符合範本，並列「開留言、關貼文審核、確認版型」手動待辦；三項打勾後才顯示給學生的網址與 QR

## ❌ 排除項（明確不做）
- 強制只能從範本建牆
- 學生上傳說明頁（QR＋拍照規範列印單）
- 班級名單對應與未繳交清單
- 多老師帳號與權限、每位老師各自的 Padlet key、雲端或資訊組伺服器部署
- 自動開留言／改版面設定（Padlet API 做不到）
- rubric 一致率報告與檢查點題庫（另案，方向已記錄）

## 📋 一段式需求規格
在 **ollama-vision-setup** 的審核頁服務（Flask，校內網址 **http://172.16.24.28:8765**，共用登入密碼）新增兩頁。「建作業牆」頁：老師選範本、填**班級、作業牆名稱**，設定**區段數量與名稱（一個區段一份作業）**與選填補充說明，系統把範本轉成 AI Recipe 指令，以 **pad02_98** 的 key 呼叫 Padlet 建牆（約 **30～90 秒**，顯示進度、失敗可重試），完成後讀回比對區段與標題是否一致，並顯示手動待辦清單（開留言、關貼文審核、確認版型），三項都打勾才顯示學生用網址與 QR。「後台」頁：列出所有建過的作業牆（班級、作業、範本、rubric、建立時間、目前繳交人數），每筆可一鍵「抓作業＋寫草稿」（背景執行、顯示進度）後進入審核頁；另可管理作業牆範本（區段、說明文字、預設 rubric）與 rubric 檔（選擇、上傳、線上編輯）。批改時每位學生每個區段評一次，評語留在該區段那篇。建牆紀錄存本機 **data/boards.json**，不進 git。老師全程只用瀏覽器，不需要開 Claude 或 agent。
