# 收工

目的：把今天的進度寫成**下一台電腦看得懂的交接**。

**這個技能不碰 git，也不碰 chezmoi。** 跨機同步靠 Google Drive。

## 步驟

### 1. 確認專案

同 `startup`：找目前工作目錄（或往上層）的 `AGENTS.md`。找不到就問使用者。

### 2. 回顧這次做了什麼

根據這次對話的實際內容整理，**不要問使用者「你today做了什麼」** —— 你自己知道。

整理成三件事：
- 完成了什麼（具體到檔案）
- 還沒完成的、進行到一半的
- 過程中發現的問題或待決事項

### 3. 更新 AGENTS.md

只在**真的有變動**時改：
- 時程表的狀態欄
- 資料夾結構（有新增重要資料夾時）
- 注意事項（發現新的雷點時）

沒變動就不要動這個檔案。

### 4. 改寫 handoff.md

**整份重寫**，不是往下追加（追加會越積越長，接手的人不知道看哪段）。

- `最後更新`：現在時間 + 電腦名稱（**實際執行 `hostname` 取得**，不要寫變數字面值；PowerShell 與 bash 都能用）
- `上次做到哪`：具體。寫「完成成果填報表的公式驗算，卡在第 3 頁的核銷比例」，不要寫「處理了一些資料」
- `下一步`：寫成**可以直接動手的動作**，1–3 項就好
- `卡關／待決`：需要等人回覆、需要使用者決定的
- `變更紀錄`：在最上面加一行今天的，**只保留最近 5 筆**，更舊的刪掉

### 5. 敏感檔案提醒

掃一下這次有沒有產生含個資或金鑰的檔案：
- 學生姓名、身分證字號、電話 → 提醒去識別化（只留座號＋班級代號）
- API key、token → 提醒不可留在會同步到雲端的檔案裡

沒有就不用特別講。

### 6. 提醒同步

最後提醒：**離開前確認 Google Drive 同步完成**（檔案總管的綠色勾勾），否則另一台會接到舊版。

### 7. 回報 checklist

```
收工完成
  AGENTS.md：<已更新／無變動>
  handoff.md：已更新（<電腦名稱>）
  完成：<一兩句>
  下次接手：<下一步第一項>
  提醒：<敏感檔案或其他，沒有就省略>
  → 離開前請確認 Google Drive 同步完成
```

## 不要做的事

- 不要跑 git commit / push
- 不要跑 chezmoi（本機不使用）
- 不要把 `handoff.md` 寫成流水帳，它是給人 30 秒讀完的
