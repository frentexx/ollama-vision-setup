# 專案初始化

為一個專案資料夾建立兩份檔案，讓三台電腦之間能無縫接手。

**這個技能不碰 git。** 跨機同步靠 Google Drive，存檔即同步。

## 先確認

1. **確認專案資料夾路徑**，並確認它在 Google Drive 底下（否則另外兩台看不到）。不在的話先問使用者要不要搬。
2. 檢查是否已有 `AGENTS.md`、`handoff.md` 或 `CLAUDE.md`。**有的話不要覆蓋**，改問使用者是要更新還是重建。

## 訪談（一次問完，不要一題一題來回）

- 專案名稱與一句話目的
- 主要產出是什麼（報表／簡報／程式／公文）
- 有沒有期限或關鍵時程
- 對應的 Obsidian 筆記位置（沒有的話問要不要建）

## 建立 AGENTS.md

寫在專案資料夾根目錄：

```markdown
# <專案名稱>

> 一句話目的
> 建立日期：YYYY-MM-DD

## 產出
<主要交付物，列點>

## 時程
| 節點 | 日期 | 狀態 |
|------|------|------|

## 資料夾結構
<用 tree 形式列出，只列有意義的層級>

## 環境與工具
- 文件處理：`%USERPROFILE%\.venvs\docs\Scripts\python.exe`（見 Obsidian 11-檔案處理工具環境）
- <其他這個專案特有的工具>

## 對照表
| 類型 | 位置 |
|------|------|
| 專案資料夾 | <Drive 路徑> |
| Obsidian 筆記 | <vault 內路徑> |
| 相關雲端檔案 | <試算表、表單等> |

## 注意事項
<這個專案特有的規則、雷點、聯絡人>
```

## 建立 handoff.md

同樣寫在專案資料夾根目錄：

```markdown
# 交接檔：<專案名稱>

**最後更新**：YYYY-MM-DD HH:MM ｜ <電腦名稱>

## 上次做到哪
<具體到「哪個檔案的哪個部分」，不要寫「處理了一些資料」>

## 下一步
1. <可以直接動手的動作>
2. ...

## 卡關／待決
<需要等別人回覆、需要使用者決定的事；沒有就寫「無」>

## 變更紀錄
- YYYY-MM-DD <電腦名稱>：<做了什麼>
```

電腦名稱**實際執行 `hostname` 取得**（PowerShell 與 bash 都能用，不要寫變數字面值），讓使用者知道上次是在哪台做的。

## 建立 CLAUDE.md（橋接檔，只有一行）

Claude Code 自動載入的是 `CLAUDE.md`，不會自動讀 `AGENTS.md`；Codex、OpenCode 等工具則讀 `AGENTS.md`。
為了讓各工具共用**同一份**藍圖，在專案資料夾根目錄建立 `CLAUDE.md`，內容只有一行：

```markdown
@AGENTS.md
```

- 已經有 `CLAUDE.md`：**不要覆蓋**。檢查裡面有沒有 `@AGENTS.md`，沒有的話問使用者要不要在第一行補上。
- **不要把 AGENTS.md 的內容複製進 CLAUDE.md**：兩份會不同步，Agent 會讀到互相矛盾的規則。
- `handoff.md` **不要**匯入：它每次收工都改寫，由「開工」時再讀。

## 建立 Obsidian 對應筆記（詢問後才做）

問使用者要不要在 vault 建一則專案筆記。要的話放 `07-專案計畫\`，內容連回 AGENTS.md 位置即可，**不要把 AGENTS.md 的內容複製一份**（兩份會不同步）。

## 完成回報

列出：建立了哪些檔案（完整路徑）、Obsidian 筆記位置，並提醒使用者：「藍圖下次開 Claude Code 會自動載入；說『開工』我會再讀交接檔，告訴你上次做到哪。」
